# MQTT v1 契约

所有业务主题以 `brics2026/<session>/cell01/` 开头。会话由启动器生成，两端必须相同。

| 后缀 | 方向 | 内容 |
|---|---|---|
| `device/inputs` | Unity → Python | 实际气缸位置、传感器、载具/物料标识、统计、可见性、急停和设备故障 |
| `ui/events` | Unity → Python | 启动、暂停、模式、上料队列等操作 |
| `control/outputs` | Python → Unity | 四状态、工序、幂等气缸目标、皮带输出、上料 ID、启动令牌 |
| `device/ack` | Unity → Python | 命令 ID 和 applied/rejected；不代表设备已到位 |
| `health/controller` | Python → Unity/观察工具 | 控制器存活信息；设备运动看门狗以有效输出为准 |

控制循环 20 Hz，输出约 5 Hz；设备完整输入 4 Hz，关键离散信号变化时立即补发。各实际气缸位置为 0–1，端点容差 0.015。关键业务消息 QoS 1、`retain=false`。诊断 ACK 最多每 2 秒一次。浏览器使用 MQTT 5，以显示公共 broker 的配额拒绝原因；普通界面操作等待控制器确认，暂停和急停立即处理。健康遗嘱仅用于可观察性，运动不依赖 broker 是否在线。

```json
{"v":1,"session":"training-001","epoch":"scene-guid","sender":"controller","peer":"process-guid","seq":123,"id":"process-guid:123","sent_ms":1789280000000,"ttl_ms":3000,"data":{"status":2,"motion_allowed":false}}
```

示例只展示部分 data 字段；完整输出见 `Outputs`，完整设备输入见 `Inputs`（`unity/Assets/Scripts/DeviceModel.cs`）。Python 输入校验要求全部轴、关键布尔信号和计数存在。发送时间基于系统时钟；时钟偏差过大会拒收，联调机器应启用自动校时。

- `seq`：每个发送进程递增；Python 按主题去重，网页对控制输出去重。
- `epoch`：Unity 每次场景重建、清料和急停/释放时更新。旧代次不重新启用。
- `feed_id`：单次上料标识，重复收到不生成新物料；同一场景最多 4096 次上料，之后需复位。
- `run_token`：来自新的启动事件 ID。网页先把本次按钮事件 ID 登记到设备，运行回报必须携带相同 ID 才能解除锁定。设备失联、暂停、隐藏或急停会清除此登记，因此较晚到达的历史启动报文也不能解除本地暂停。
- 有效对端数据超过 3 秒未到，冻结设备/暂停控制器；初次握手、重连都不会自行开始生产。
- 同一活动会话仅绑定一个仿真进程、一个控制器；刷新后的新仿真等待旧实例租约过期。随机会话不是身份认证。
- 控制器重启时如果设备报告在制载具或夹持，进入暂停并报告 `RECOVERY_RESET_REQUIRED`，复位后重来。
- 网页急停先本地清料锁止，紧接着发布新代次输入。远程状态字段不能释放本地急停锁。
- 初始化可以在状态 0 中回原位；状态 2 全部工艺运动冻结，计时冻结。网络与指示灯继续运行。

缺失的竞赛地址不推测填写，具体映射见 `io-map.json`。传感器根据 C# 设备模型中的实际位置和物料姿态属性产生；Python 从颜色/方向输入判断类别，Unity 仅按实际放料位置计数，不按颜色自行分拣。

`RELEASE` 等挡停缩回反馈，之后 `RELEASE_DELAY` 累计 10 秒运行时间（截图 160 所示延时），同时要求载具离开后才挡停复位。暂停期间延时冻结；这些语义步骤没有冒充未提供的原题全部步骤号。
